    \section{Tecnologías empleadas}\label{tec}
        
    En el desarrollo del proyecto y de la memoria se ha utilizado distintas herramientas y recursos. A continuación, se incluye una breve descripción de cada una de ellas. Se pueden dividir en dos bloques aquellas tecnologías empleadas en el desarrollo de la memoria y las utilizadas en el desarrollo del prototipo.

    \subsubsection{Herramientas empleadas en el desarrollo de la memoria.}
    \begin{itemize}
        \item Overleaf: es un editor LaTeX en línea que permite realizar documentos de texto complejos. La memoria de este trabajo se ha escrito íntegramente con esta herramienta, utilizando como base la plantilla proporcionada desde la universidad.\cite{Overleaf}
        
        \item Papeeria: \textcolor{red}{Similar a Overleaf, pero permite mayor tiempo de compilación gratuito.}
        
        \item LaTeX: es un sistema de comandos para composición de textos que permite crear documentos complejos con alta calidad tipográfica, como los trabajos científicos y técnicos.

        
        \item Draw.io: es un servicio web gratuito que permite crear distintos diagramas. Esta herramienta se ha utilizado para crear diferentes diagramas del trabajo como el diagrama de casos de uso. \cite{Diagrams.net}
        
        \item Github: es una plataforma en la nube que permite almacenar, compartir y trabajar de forma colaborativa proyectos en forma de repositorios. En los repositorios se pueden almacenar ficheros de código, de texto o imágenes... Además, estos repositorios sirven para presentar o compartir trabajos, seguir los cambios realizados a lo largo del tiempo u obtener feedback del proyecto por parte de otros usuarios. En este trabajo se ha utilizado para recopilar todos los ficheros en un único lugar desde donde poder ir viendo el avance del proyecto.\cite{gitHub}
        
        \item Microsoft Office 365: son un conjunto de aplicaciones de oficina que mejoran la productividad, que incluyen aplicaciones de edición de texto, herramientas de comunicación, de análisis de datos, servicios en la nube... En el trabajo se ha utilizado como un apoyo más, utilizando documentos de Word para recopilar información, Excel para la planificación temporal o PowerPoint para mejorar imágenes, crear esquemas y realizar la presentación de la defensa del trabajo.\cite{microsoft365} 

        
        \item Inteligencia artificial copilot: es un asistente de inteligencia artificial de Microsoft que ayuda a resumir, redactar y automatizar tareas. En el trabajo se ha usado como una herramienta más para obtener imágenes personalizadas para el proyecto como el diseño de las pantallas, obtener la bibliografía en LaTeX de forma automatizada u obtener una organización inicial de los apartados del documento, aunque luego se ha ido modificado en función de las necesidades del proyecto.\cite{copilot2025}
        
    \end{itemize}

    \subsubsection{Herramientas empleadas en el desarrollo del prototipo.}
    \begin{itemize}
        \item Visual Studio Code: es un editor de código de Microsoft que permite crear y modificar todos los ficheros necesarios para el funcionamiento de la aplicación. Este software permite visualizar toda la estructura de archivos del proyecto y ejecutar ficheros ya que cuenta con un terminal de comandos. Además, se pueden descargar distintas extensiones y conectarse a GitHub en función de las necesidades del proyecto.\cite{vscode} 
        
        \item React Native: es una biblioteca de JavaScript que permite desarrollar aplicaciones móviles nativas multiplataforma (tanto en Android como en iOS) a partir de un único código JavaScript.  Cuenta con cinco elementos principales para construir las interfaces de usuario: View, Text, Image, ScrollView y TextInput.\cite{reactnative} 
        
        \item Expo: es una colección de herramientas que simplifican el desarrollo de aplicaciones con React Nactive. Además, permite realizar testeos tanto en el navegador, como en dipositivos móviles o simuladores. En concreto, en este trabajo inicialmente se ha utilizado Expo Snacks, que es un entorno interactivo online, para visualizar las primeras fases del frontend de la aplicación con correcciones y sugerencias automáticas y ya pasar el código a Visual Studio Code.  Más tarde se ha utilizado Expo Go que es una aplicación móvil que permite experimentar la aplicación multiplataforma desarrollada en un dispositivo móvil, simplemente escaneando un código QR.\cite{expo, expo_snack, expo_go}

        \item Node.js: es un entorno de ejecución JavaScript gratuito, de código abierto y multiplataforma que permite construir aplicaciones de red escalables. Se utiliza para poder conectar la interfaz de usuario con la base de datos.\cite{nodejs}
        
        \item MariaDB y HeidiSQL: es una base de datos relacional que permite el acceso a sus datos con SQL. Fue desarrollada como un software de código abierto por lo que ofrece un servicio rápido, escalable, versátil y robusto. En el proyecto se usa MariaDB para crear la base de datos de AlertRes y utilizarla en el prototipo\cite{mariadb}. La interfaz gráfica utilizada para trabajar con MariaDB es HeidiSQL que permite crear de forma sencilla las diferentes tablas de la base de datos de AlertRes y visualizar los datos recogidos en ellas.\cite{heidisql} 
        
        \item Como lenguajes de programación para el desarrollo del prototipo se han utilizado JavaScript, que se utiliza principalmente para desarrollo de páginas web y aplicaciones; y SQL que se utiliza para gestionar, consultar y modificar la información almacenada en bases de datos relacionales. 
        

    \end{itemize}

    \subsubsection{Requisitos No Funcionales}
En este apartado se presentan los requisitos no funcionales que corresponden a la calidad del funcionamiento, correspondientes a cómo debe de ser la aplicación para ofrecer la mejor experiencia.

    
    \begin{itemize}
        \item \textbf{Seguridad}: La información almacenada y manejada en la aplicación debe estar protegida, mediante mecanismos de autentificación y/o cifrado, cumpliendo con todas las normativas de manejo de datos sensibles.
        
        \item \textbf{Usabilidad}: la aplicación debe poder usarse de forma intuitiva, por lo que requerirá de una interfaz sencilla de utilizar.
        
        \item \textbf{Memorabilidad}: el funcionamiento de la aplicación deberá ser fácil de recordar tras no haberla utilizado durante un periodo de tiempo.

        \item \textbf{Accesibilidad}: la aplicación debe poder ser accesible tanto para personas con algún tipo de discapacidad como para las que no. 
        
        \item \textbf{Compatibilidad}: la aplicación debe ser compatible con distintos dispositivos y sistemas operativos.
        
        \item \textbf{Eficiencia}: debe lograr cumplir los objetivos del usuario, con el menor coste comutacional y temporal. Además el sistema debe estar preparado para funcionar bajo condiciones de alta demanda, con conectividad limitada y garantizando su disponibilidad continuada.
        
        \item \textbf{Escalabilidad}: el sistema debe estar diseñado para poder adaptarse al crecimiento en la cantidad de usuarios y el volumen de datos gestionados.
        
        \item \textbf{Efectividad}: se deben cumplir con exactitud con los requisitos funcionales.
        
        \item \textbf{Errores}: la aplicación debe tener una tasa de error baja y en caso de errores proponer posibles soluciones a esos problemas.
        
        \item \textbf{Satisfacción}: se deberá conseguir que el usuario se encuentre satisfecho de forma general con la aplicación.
        
    \end{itemize}

    \subsection{Riesgos}
    
    El uso de una herramienta de estas características, destinada al apoyo de la búsqueda y rescate de personas desaparecidas, conlleva una serie de riesgos que se deberán intentar minimizar. Al tratarse de una herramienta que gestiona información sensible en un entorno de emergencia, es fundamental que su desarrollo y utilización se ajusten a la legislación vigente, se acompañen de planes de formación adecuados, protocolos de actuación ante incidentes y revisiones periódicas que garanticen su fiabilidad y seguridad.

    Uno de los principales riesgos está relacionado con la seguridad y la privacidad de los datos. La exposición a vulnerabilidades técnicas puede derivar en fugas de información o ciberataques que comprometen la integridad del sistema, y una gestión inadecuada de los datos puede acarrear consecuencias éticas graves y sanciones legales.

    Durante el desarrollo y despliegue de la aplicación pueden surgir problemas técnicos como la conectividad limitada, que afectaría directamente a la comunicación y a la geolocalización en tiempo real. Además, un uso inapropiado por parte de usuarios no capacitados o en contextos no previstos puede tener consecuencias graves, incluso fatales, por lo que es imprescindible diseñar la herramienta contemplando una amplia variedad de escenarios operativos y establecer límites claros en sus funcionalidades para evitar el problema. También se debe considerar que algunos frupos de rescate pueden contar con sus propios dispositivos o sistemas, lo que podría dificultar la adopción de la aplicación si no se prevé una integración adecuada con otras plataformas y tecnologías.

    Por otro lado, como se proponen a futuro algunas funcionalidades basadas en inteligencia artificial, como las herramientas de predicción, es importante tener en cuenta que también pueden derivar en riesgos. Por ello, deben entenderse como apoyo complementario y no como sustituto del criterio profesional,ya que en ningún caso deben reemplazar la valoración experta de los equipos de rescate.
    
    Para minimizar el impacto de todos estos riesgos, es necesario definir estrategias específicas que refuercen la seguridad, la fiabilidad y la ética del sistema. Algunas de estas estrategias pueden contemplar desde la verificación de usuarios hasta la implementación de protocolos de respuesta ante incidentes, pasando por la formación continua y la evaluación constante de la herramienta en su contexto operativo.
